## The six goals, in Tamara's words, with what we already know

### 1. One repo per state per session
E.g. IL 2025 in one repo, IL 2026 in another. Special sessions: maybe attached to a larger
one, undecided.
- `actions/pipeline-manager/close_session.py` already exists for this: human-triggered,
  transfers a repo to an archive org (default `govbot-archive`), renames it with the
  session id, GitHub-archives it, and creates a fresh repo for the next session. Requires
  `locales.<code>.session` set in the config first. It has never been run at scale.
- **Collision risk:** `govbot-archive` already holds a bare `<state>-legislation` for most
  states: an orphaned, unarchived generation (created 2025-11-26, abandoned 2026-07-15,
  3–27 MB). `close_session.py` writes into that org by name. Resolve before running it.

### 3. PRIORITY: convert per-action JSON log files into one JSONL file
Today each bill has a `logs/` folder with one JSON file per action/vote
(`<YYYYMMDDTHHMMSSZ>.<type>.json`), which means thousands of files per repo. Goal: append
to a single `.jsonl` per bill (or per session) instead. Tamara thinks this code may already
exist on recently pushed repos. **First step: check `actions/format` and a few recently
updated `govbot-data` repos to see whether it exists**, then plan converting every repo to
that layout. Second-order effects to check: `govbot logs`, `govbot load` (DuckDB),
`scripts/build_site_slices.py`, the weekly audit's activity checks, and
`actions/pipeline-manager/scripts/audit-last-real-activity*.sh` all read the per-file
`logs/` layout or its filenames.
